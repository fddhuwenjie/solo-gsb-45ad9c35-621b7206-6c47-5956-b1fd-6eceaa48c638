# 🎭 旋转舞台走位复核台

用于复核旋转舞台（转台）演出走位的安全工具：设定舞台半径与演员/道具的安全半径，
按时间录入**位置关键帧**（随台实体为**局部坐标**，固定道具为**全局坐标**）和
**全转台共享的转台角度关键帧**，系统自动插值换算为全局坐标，
每 **50ms** 检查安全圆**相交**与**越界**，并把连续命中合并为风险区间。

- **随台实体**（演员/道具，`随台`）：站在转台上，同一时刻共用同一个转台姿态，
  不可能出现同转台两个实体各转各的角度；
- **固定道具**（`固定`）：钉在地面上，坐标就是全局坐标，转台转动时它不旋转。

还支持**队形约束编排（有向跟随组）**：把实体组织成编队，为每条
「主实体 → 从属实体」关系设置相对距离与角度；编辑主实体关键帧或共享转台姿态时，
服务按随台/固定坐标语义把从属实体传播定位、自动生成/更新其关键帧。
约束图成环、从属实体同时被多个主实体驱动、或传播后关键帧越界，都会
**整单拒绝**并指出冲突链。

技术栈：Python · FastAPI · SQLite · 原生 JavaScript · SVG · Docker Compose。

---

## 一条命令启动

```bash
docker compose up -d --build
```

启动后浏览器访问：

> **http://localhost:8000**

停止：

```bash
docker compose down          # 停止
docker compose down -v       # 同时清空数据（SQLite 存在卷 stage-data 中）
```

数据通过 Docker 卷 `stage-data` 持久化，容器重启后走位数据不丢失。

> 端口冲突时修改 `docker-compose.yml` 中 `"8000:8000"` 左侧端口即可。

## 操作方法

### 基本设置
- 顶栏 **舞台半径(m)**：修改后立即重算全部风险。
- 左侧 **＋演员 / ＋道具**：新增实体会自动在 0 秒放置一个初始关键帧。
- 选中实体后可编辑**名称、类型、运动方式（随台/固定）、安全半径、颜色**，或删除该实体。
  - **随台**：随转台旋转，关键帧坐标为转台局部坐标；
  - **固定**：钉在地面不旋转，关键帧坐标为全局坐标（适合固定在地面的道具）。

### 录制关键帧（两种方式）
1. **舞台直接拖动**（最常用）：在时间轴上定位到某一时刻，直接在俯视图中拖动
   演员/道具，松手即在该时刻保存一个位置关键帧；随台实体自动按当前共享转台角度
   反算为局部坐标，固定道具直接保存全局坐标。
2. **表单录入**：
   - 「转台角度 @ 当前时间」面板填写**转台角度(°)** 并「记录转台帧」，
     该角度对**全部随台实体**同时生效（同一时刻只有一个转台姿态）；
   - 选中实体，在「实体关键帧 @ 当前时间」面板填写
     **局部 X / 局部 Y**（固定道具显示为全局 X/Y），点击「记录关键帧」；
   - 「读取插值」可把当前插值结果填入表单，便于微调。
   - 同一时刻重复记录即为**覆盖**；
   - 时间按 50ms 对齐；
   - 面板中的时间胶囊点击可跳转，点 × 删除该关键帧。

### 时间轴与播放
- 底部时间轴可**点击/拖动**任意定位；
- **▶ 播放 / ⏸ 暂停**按钮，或按 **空格键**；
- **← / →** 方向键逐帧（50ms）移动，按住 **Shift** 跳 1 秒；
- 播放到总时长末尾自动暂停。

### 查看与跳转风险
- 时间轴上方红色块 = **相碰**，橙色块 = **越界**，点击直接跳到区间起点；
- 左侧「风险区间」列出全部区间（类型、相关实体、起止时间），点击跳转；
- **← 上一风险 / 下一风险 →** 按钮顺序跳转；
- 播放/拖动时，正在发生的风险会在舞台上高亮：涉事实体的安全圆变红，
  相碰双方用红色虚线连接，风险列表同步高亮。

### 编队约束（有向跟随组）
- 左侧「编队约束」面板 **＋ 新建编队**，可改名/换色；舞台上同编队的关系用
  同色**带箭头连线**预览，连线中点标注距离/角度；实体列表里 `主` / `从`
  角标标明其在约束图中的角色。
- 在编队编辑器里选择**主实体 → 从属实体**，填写**相对距离 (m)** 与
  **相对角度 (°)** 后「添加跟随关系」；关系列表中可直接改距离/角度、或删除。
- **传播**：
  - 直接在舞台**拖动主实体**（或表单记录其关键帧）时，从属实体按约束沿链
    被带动并在同一时刻生成/覆盖关键帧；
  - 编辑**共享转台角度**时，随台从属实体保持队形（局部相对关系不变），
    固定从属实体则在全局坐标中被重新定位；
  - 拖动过程中页面会即时预览编队形态，松手时才**原子提交**到后端。
- **整单拒绝**（页面顶部红色横幅会给出冲突链）：
  - **成环**：跟随关系构成有向环（如 甲→乙→丙→甲）；
  - **多主**：一个从属实体同时被两个主实体驱动（`UNIQUE(follower_id)` 兜底）；
  - **越界**：传播后某个从属实体的安全圆超出舞台。
  - 以上任一情况，本次编辑（含主实体/转台那一个关键帧）**整体回滚、不写库**。
- 相对角度以**主实体坐标架**为 0° 基准：随台主实体用转台局部架
  （角度随转台一起转），固定主实体用全局架（永远指向舞台的同一方向）。

## 计算规则

1. 实体位置在相邻关键帧之间**线性插值**；关键帧范围之外保持首/末帧。
   随台实体记录的是局部坐标，固定道具记录的是全局坐标。
2. **转台角度沿最短弧插值**：增量归一化到 (−180°, 180°]，且角度是
   **全转台共享**的关键帧——同一时刻所有随台实体共用同一个角度。
   例如 350°→10° 顺时针走 20°；0°→180° 按负向走 −180°；
   0°→360° 因最短弧增量为 0 而不转动（如需转整圈请拆成两个半圈关键帧）。
3. 随台实体的局部坐标 `(x, y)` 按转台角度 θ 换算为全局坐标；
   固定道具不旋转（θ 恒为 0，全局坐标即录入坐标）：

   ```
   gx = x·cosθ − y·sinθ
   gy = x·sinθ + y·cosθ
   ```

4. 从 0ms 起每 **50ms** 采样一次：
   - **相碰**：任意两个实体的全局圆心距 `< r₁ + r₂`（严格相交，相切不算）；
   - **越界**：`|全局坐标| + 安全半径 > 舞台半径`。
5. 同一类型、同一对/同一个实体的相邻命中样本**合并为一个风险区间**，
   区间右端点顺延一个采样步长（50ms）。

任意编辑（舞台半径、实体增删改、随台/固定切换、实体或转台关键帧增删改）
都会**立即在后端重算**、写入 SQLite，并把最新状态返回给前端。

6. **队形约束传播（schema v2）**：每个从属实体至多有一个主实体，关系存
   相对距离 d 与相对角度 α（以主实体坐标架为基准）。从属实体全局位置由
   主实体全局位置推出：

   ```
   从.g = 主.g + d·( cos(主坐标架角度 + α), sin(主坐标架角度 + α) )
   ```

   - 主实体坐标架角度：随台主实体 = 当前转台角，固定主实体 = 0；
   - 从属实体落帧时按自身语义换算：随台 → 反算为转台局部坐标，固定 → 直接存全局坐标；
   - 编辑主实体关键帧时沿约束图拓扑传播给全部下游从属实体；编辑转台角度时
     只为位置受转台影响的从属实体落帧（固定主→固定从的链不受影响）；
   - 提交前先在「投影场景」中算完整条链：**成环 / 多主 / 传播后越界**
     （`|全局坐标| + 安全半径 > 舞台半径`）一律 HTTP 409 整单拒绝，
     响应体 `detail` 含 `code`、`message` 与冲突链（`chain_names` /
     `chains_names`），通过后才统一写库，保证原子性。

首次启动会自动载入一份演示走位（包含相碰、旋转致碰、越界各一段），可直接播放查看。

> **旧数据迁移**：旧版把转台角度挂在每个实体的关键帧上，升级启动时会自动迁移到
> 共享转台关键帧（同一时刻角度冲突时取最早录入的一条），已有实体默认按「随台」处理，
> 需要固定的道具在实体编辑器里改为「固定」即可。
> 编队约束为 schema v2 新增，旧库启动时会自动补建 `formation_groups` /
> `formation_links` 两张表（默认为空，不影响已有走位数据）。

## 接口一览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/state` | 获取完整状态（设置、实体与位置关键帧、共享转台关键帧、风险、总时长） |
| PUT | `/api/settings` | 更新舞台半径 `{stage_radius}` |
| POST | `/api/entities` | 新增演员/道具 `{name, kind, radius, mounted}` |
| PUT | `/api/entities/{id}` | 修改实体字段（含 `mounted`：`rotating` 随台 / `fixed` 固定） |
| DELETE | `/api/entities/{id}` | 删除实体（级联删除其关键帧） |
| PUT | `/api/entities/{id}/keyframes` | 新增/覆盖位置关键帧 `{t_ms, x, y}`（随台为局部坐标，固定为全局坐标） |
| DELETE | `/api/entities/{id}/keyframes/{t_ms}` | 删除某时刻位置关键帧 |
| PUT | `/api/turntable/keyframes` | 新增/覆盖共享转台角度帧 `{t_ms, angle}`（全部随台实体共用；触发队形传播） |
| DELETE | `/api/turntable/keyframes/{t_ms}` | 删除某时刻转台角度帧 |
| POST | `/api/formations` | 新建编队 `{name, color?}` |
| PUT | `/api/formations/{id}` | 修改编队名称/颜色 |
| DELETE | `/api/formations/{id}` | 删除编队（级联删除其中关系） |
| POST | `/api/formations/{id}/links` | 新增跟随关系 `{leader_id, follower_id, distance, angle}`；成环/多主/自指返回 409 + 冲突链 |
| PUT | `/api/formations/links/{id}` | 修改关系 `{distance?, angle?, group_id?}`（可用于跨编队转移） |
| DELETE | `/api/formations/links/{id}` | 删除一条跟随关系（从属关键帧保留，之后不再跟随） |

**409 冲突响应**：写主实体关键帧、写转台角度帧、增改跟随关系时，若违反队形约束，
HTTP 状态码为 `409`，响应形如：

```json
{
  "detail": {
    "code": "cycle | multi_driver | out_of_bounds | self_link",
    "message": "人类可读说明",
    "chain_names": ["主实体", "从属实体"],
    "chains_names": [["旧主", "从属"], ["新主", "从属"]]
  }
}
```

整次编辑被原子拒绝，数据库保持编辑前状态。

旧版 `PUT .../keyframes` 请求里带 `angle` 字段仍被接受，会同时写入共享转台角度帧。

所有写接口都会返回更新后的完整状态（含重算后的风险区间）。

## 本地开发（不用 Docker）

```bash
cd backend
pip install -r requirements.txt
uvicorn main:app --reload --port 8000
```

SQLite 数据库默认位于 `backend/data/app.db`，可用环境变量 `DB_PATH` 指定位置。
